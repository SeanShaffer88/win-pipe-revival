# Revival provenance and 0.2.0 progress

Upstream: https://github.com/goodtrailer/win-pipe
Base: 8c8294c2fd43a62c30b3b4f47a04a9dbde9b7633
Initial lifetime-fix commit: 5de3903bc2f803f78dba62b694fa20b2d657d3b7
License: ISC; upstream LICENSE retained unchanged.
Backlog: WR-007. Development began 2026-10-21.

The first milestone reproduced a move-assignment timeout and repaired receiver-state lifetime. It passed six Clang Windows x64 tests.

The 0.2.0-rc.1 candidate adds MSVC discovery/initialization, cancellable overlapped I/O, shared worker ownership, exception-contained callbacks, bounded assembly and connection handshakes, per-message sender connections, concurrent senders, restart recovery and UTF-8 names. It removes blocking FlushFileBuffers and stale retained sender handles.

A regression found overlapped ERROR_MORE_DATA reads returning zero through the immediate byte-count argument; the assembler now retrieves the completed fragment byte count. A receipt/confirmation exchange prevents clients closing before server consumption and prevents server disconnect from discarding an unread receipt. This changes the wire protocol: both ends must use the revival header.

Validation targets are MSVC 19.51 on x64 and x86 in Debug and Release, and LLVM-MinGW Clang 23.1.3 on x64 Release. The 19-case suite includes 8 concurrent send threads/400 messages and 4 child processes/100 messages per full pass, plus timeout, payload, lifecycle, connection-abort and resource checks. Final per-target evidence is bundled separately and generated by tests/build.ps1. The example also passes MSVC /analyze with warnings treated as errors.

For 0.2.0, state/event/pipe/thread/buffer failures are deterministically injected at acquisition boundaries and cleanup/recovery is tested. This does not exhaust system-wide resources. PipeLog provides an application-result acknowledgement after its output stream flush; the transport itself still provides no persistence or exactly-once guarantee. Callbacks must return; stop cannot safely terminate arbitrary user code. Security-principal configuration is outside this API. See README.md and REVIEW.md for the contract and review.

The stable scope uses 24 transport cases across five local configurations (MSVC x64/x86 Debug/Release and Clang x64 Release), with 336 passing executions when x64 Release is repeated ten times. Each configuration also runs the real PipeLog integration and separate-process example smoke test. Publication is gated on an exact-commit successful GitHub CI run; the release page records that evidence.
